Understanding Unix Cron Syntax & Expressions

The Cron daemon is a time-based job scheduler foundational to Unix, Linux, and modern containerized server systems like Kubernetes (CronJobs) and cloud automation (AWS CloudWatch Events, GitHub Actions). Crontab configuration files specify commands to run periodically at fixed times, dates, or intervals.

However, compact crontab syntax can easily lead to costly scheduling blunders—such as triggering a heavy database dump every minute instead of once per hour. This interactive parser unpacks each field visually, validates wildcard constraints, and renders predictable chronological execution dates.

Cron Syntax Operators Guide

  • Asterisk (*): Wildcard matching all possible values in that field.
  • Comma (,): Value list separator allowing multiple specific integers (e.g. 1,15,30).
  • Hyphen (-): Specifies an inclusive numeric range (e.g. 9-17 for working hours).
  • Slash (/): Step intervals. */10 in the minute column executes every 10 minutes.

Frequently Asked Questions (FAQ)

Q: Is Sunday represented as 0 or 7 in crontab?

In standard Linux/BSD crontab implementations, both 0 and 7 represent Sunday (0 = Sunday, 1 = Monday, ..., 6 = Saturday, 7 = Sunday). This parser safely treats both 0 and 7 as Sunday.

Q: Does this parser execute in my browser?

Yes. 100% of the lexical parsing and upcoming timestamp calculations run inside your browser. No schedule parameters or server configurations are transmitted to remote networks.

Q: How do Day-of-Month and Day-of-Week interact when both are set?

In standard Unix cron, if both the day-of-month and day-of-week fields are constrained (not wildcard *), the command runs when EITHER the day of the month OR the day of the week matches (OR logic).
