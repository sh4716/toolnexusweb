UUID / GUID 技术规格与工程选型深度解析

通用唯一识别码（UUID，Universally Unique Identifier）由开放软件基金会（OSF）制定并纳入 RFC 4122 标准，是一种长达 128 位的数字标识符。其设计的核心目标在于让分布式计算环境中的任意节点无需中央调度注册机构，即可各自独立创建全球唯一的 ID。在微软 Windows 生态体系中，它通常被命名为 GUID（Globally Unique Identifier），两者在底层规范与算法上完全等价。

🎲 UUID Version 4 (随机数版本)

标准 UUID 表现为 36 个字符（含 4 个连字符：8-4-4-4-12）。在第 13 位字符固定标注版本号 4，第 17 位标注变体 8/9/a/b。除去固定的 6 个元数据位，其余 122 位全部来自密码学随机数，提供多达 5.3 × 10^36 种组合。

🛡️ Web Crypto 硬件级安全熵源

市面上许多在线工具仍滥用 JavaScript 的 Math.random()，其伪随机种子极易被逆向预测。ToolNexus 严格采用 crypto.randomUUID() 及 getRandomValues()，直接从操作系统内核熵池获取硬件级真随机数。

🗄️ 数据库主键选型建议 (v4 vs v7)

UUID v4 的完全离散随机性是分布式跟踪 ID、OAuth State、会话令牌的理想选择；但在高并发写入的 MySQL InnoDB 聚簇索引中，完全随机写会导致 B+ 树频繁页分裂。建议在此类高吞吐存储场景配合前置时间戳或选用新一代 UUID v7。

常见问题解答 (FAQ)

Q: 为什么生成的 UUID 可以去除横杠或加上大括号？

虽然 8-4-4-4-12 连字符分隔是 RFC 4122 的标准 canonical 表现形式，但在注册表注册 COM 组件时需要大括号包装（如 {00000000-0000-...}），在 URL 或紧凑数据库存储时常去除连字符保留 32 位十六进制纯字符。本工具支持一键自定义勾选。

Q: 一次性批量生成 500 个 UUID 会有重复吗？

绝不可能。根据生日悖论计算，若要达到 50% 的冲突几率，需要连续生成超过 2,700,000,000,000,000,000（2.71 百亿亿）个 UUID。在单个批次或单体应用生命周期内，重复概率趋近于绝对零。

Q: 生成过程是否会连接外部 API 或泄露网络特征？

完全不会。Version 4 不依赖您的 MAC 地址或 IP 地址，所有逻辑在本地浏览器引擎中纳秒级运行，完全离线运行，安全合规。
